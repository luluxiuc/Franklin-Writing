# 富兰克林写作

**一个刻意不做 AI 评判的写作练习工具。**

导一篇文章进去,读原文,搁几分钟,凭记忆重写一遍,然后跟原文逐句并排对照。系统负责切分、提示、隐藏、延迟、记录。**理解与评判完全由你自己完成。**

网页版,跑在你自己电脑上,数据全部留在本地。只有「把原文变成逐句提示」这一步会用到一次大模型,而且不填 Key 也能用。

## 先说结论:这个项目为什么不做 AI 评分

这个项目原本的设计核心是一套「作者近似度」评分与差距诊断引擎:你临摹一段范文,AI 告诉你哪里不像作者、为什么不像、下一步怎么改。

**我们实测之后把这个引擎整个删掉了。不是因为它做得不够好,而是因为实测出它在做一件跟它宣称在做的不一样的事。**

5 位独立的 LLM 裁判、18 个匿名文本块、预注册的判定标准,结果:

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| 真实文本被误判为模仿 | **0%** | 5 位裁判全部判对 8/8 |
| 植入明显缺陷的模仿被识破 | **100%** | 5 位裁判全部识破 5/5 |
| **无缺陷的模仿被识破** | **0%** | 多数裁决;5 位中 3 位为 0/5 |

前两行看着像「能力很强」。**第三行说明它不是在做风格判断,而是在做缺陷检测**——靠一份可枚举的黑名单(直接命名情绪、"仿佛在诉说着什么"、解释性连接词、抽象收尾),而不是靠"像不像这位作者"。

> **判别力 100% 来自「有没有明显缺陷」,0% 来自「像不像作者」。**

### 关键不是判不准,而是判错的方向可以预测

判不准只是噪音,可以接受。真正让我们删掉这个引擎的是:**裁判拒绝的恰恰是作者本人的标志性手法。**

| 裁判的理由 | 事实 |
| --- | --- |
| 「只给记忆的元陈述」是破绽,真实写法会让那个东西本身被描述出来 | 该作者大量使用元陈述:「其余的都记不清,数不出了」「也许十二红只是一个名目」「这一点是我没有记错的」 |
| 「节奏由氛围而非信息推进」 | 同类判据会同样打击该作者确认无疑的真实段落:「有的样子蠢,有的秀气」「白嘴吃也可以」 |
| 「现实里一个线轴只缠一色线,属对实物无经验造成的漏洞」 | **对文本的误读**(原文是两个线轴),裁判**编造语言证据**来支撑一个风格判断 |
| 「结尾留白,感伤来得过于准时」 | 与该作者「我也没问」「白嘴吃也可以」的收束方式同类 |
| 「省掉『的』,是刻意制造的断裂」 | 把精确的语言判断为刻意断裂 |

如果把这套反馈接进训练,用户照改的结果是:**删掉"我也没问",把留白补成解释,给句子补上主语和连接词。**

**他会越来越像一个文从字顺的普通写作者,而不是他要学的那位作者。**

### 为什么"换个更强的模型"解决不了

模型永远不会直接比较「你的文本」与「作者本人」,它比较的是「你的文本」与「它对作者的理解」。这两者之间的差距不会因为模型变强而消失——**更强的模型只是产出一个更精细的代理指标,而更精细的代理指标仍然是代理指标**。

还有四层结构性的理由:

1. **描述本身可能指向错误的层级。** 实测中,连"这位作者善用短句"这种最基础的印象都是错的——他的句长均值 17.8 字,最长连续短句串只有 2 句;真正的特征在下一级单位:小句均长 7.5 字。用「短句」当训练目标,方向从一开始就是反的。
2. **只拿到单篇文本的读者(无论模型还是真人)看不到决定"像不像"的很大一部分信息。** 作者没写的那些选择、他同时在跟谁对话、他刻意避免什么。**所以有些分歧不是模型的缺陷,是任务的缺陷。**
3. **剩下主观那一层,真人之间也不一致**,而且分歧恰好集中在「写得称职、但不确定是不是本人的文本」——也就是用户训练中会遇到的全部文本。如果人类之间都不一致,那就不存在一个可以对齐的「人类共识」。
4. **误判的代价是不对称的。** 判对了,用户得到一条提示;判错了,用户删掉一处本来正确的写法,**而这种损失不可逆,且用户无从察觉**——他没有理由怀疑一个措辞专业、引用了原文、条理清晰的判断。

> **在"帮助用户学会写作"这件事上,一条错误的指导比没有指导更糟。**

而删掉判断的代价是零:富兰克林方法的驱动力本来就在「阅读 → 脱离原文重构 → 延迟 → 并置对照」这些**动作本身**,不在判断上。富兰克林本人就是这么练的——**他的评判是他自己做的**。

### 替代解释已被排除:不是"嫌我的稿子太短太薄"

归一化特征对比:

| 组 | 具体名物密度 | 动词密度 | 连接词 | 情绪词 | 平均字数 |
| --- | --- | --- | --- | --- | --- |
| A 真实(8 段) | 4.7 | 4.1 | 0.39 | 0.25 | 87.8 |
| 无缺陷模仿(5 段) | **9.2** | **6.2** | 0.00 | 0.00 | 59.4 |
| 有缺陷模仿(5 段) | 2.4 | 1.1 | **4.38** | **1.40** | 73.0 |

**模仿稿的名物密度比原文还高(9.2 vs 4.7)**,"信息量薄厚"这个解释站不住。真正可机械区分的只有**连接词与情绪词**:有缺陷组高,无缺陷组为零——**与原文一样为零**。

**结论收紧为:裁判能可靠检出的只有显式植入的缺陷标记;一旦模仿稿在这两项上追平原文,判定即降到随机。**

### 纯计算部分的实测(零模型调用)

语料:一篇 1351 字的真实散文。

| 指标 | 实测值 |
| --- | --- |
| 句长 | 均值 **17.8** 字,标准差 10.0,最短 1,最长 43 |
| 小句长 | 均值 **7.5** 字,标准差 3.8 |
| **最长连续短句串(≤8 字)** | **2 句** |
| 连接词密度 | **0.74 / 百字** |
| 具体名物 | 47 种,共出现 165 次(约每 8 字一个实物) |
| 逗号密度 | 6.9 / 百字(逗号句号比 1.48) |
| 情绪词 | 仅 2 次,且**两处都不是陈述情绪** |

**两个被实测推翻的通用结论:**

- **「善用短句」是错的。** 句长均值 17.8 字、最长连续短句串仅 2 句——从句子层面看节奏并不短促。真正的特征在下一级单位(小句均长 7.5 字)。
- **「不写情绪词」的说法不准确。** 全文直接情绪词只有 2 次"高兴",分别是否定式和条件状语(一……就……),**没有一处以情绪为谓语**。正确表述是「不把情绪词用作主句谓语」。

**同一批手写阈值规则做出的判定还暴露了四个结构性假阳性**(详见[决策报告](docs/研究/为什么不做LLM判断评分.md)):把作者原文判为"偏离作者"、在错误的层级上取样、把某种低频特征当逐段必备项、**写得更接近作者的稿子反而拿到与写坏的稿子相当的严重问题数**。

**这些失效没有一条能靠调阈值修好**——它们不是参数问题,而是建模错误。

## 它做什么

**只做一个纯工具,帮你更便捷地使用富兰克林写作法。**

| | 系统负责 | 你负责 |
| --- | --- | --- |
| 切分 | 按节(阅读单位)与段(练习单位)切开,一个字不丢 | 确认或重切 |
| 提示 | 给**每一句话**配一条短提示,后台可提前批量备好 | 用它当抓手,或关掉 |
| 隐藏 | 写作阶段原文的任何一个字都不出现 | — |
| 延迟 | 读完到能写之间强制等待(默认 3 分钟,可调 0–240) | 等,或者去练别的段 |
| 对照 | 逐句 LCS 对齐并排,机械标出命中与缺漏 | **自己看,自己说** |
| 记录 | 逐句笔记、整段观察、每一轮的稿子,全留在本地 | 写下来 |

**关键设计点:**

- **提示是一句一条,不是整段概括。** 富兰克林原本的做法就是给每句话记一条短提示(他自己写的是 *short hints of the sentiment of each sentence*),搁几天,再看着提示把整篇写回来。而且这个练习要练的本来就是「写好每一句话」,所以提示的单位就该是句子。段落概括会把原文重新组织一遍——那个结构是模型的,不是你的。
- **提示只给"这句讲了什么",不给措辞、不给写法、不评价。** 而且工具会机械检查:任何一条里只要出现连续 8 个字以上与原文逐字相同,这条就丢掉。
- **对照用最长公共子序列对齐,不是第 n 句对第 n 句。** 你漏写一句,后者会让后面全部错位,那显示的是假信息——比不显示更糟。
- **延迟放在「读完」和「开始写」之间。** 刚读完就写,写出来的是眼睛里残留的字;等几分钟再写,写出来的才是记住的东西。放在交稿之后只是防止偷看,那防的是作弊,不是帮助记忆。
- **笔记跟着书走,不跟着某一轮走。** 单句练习记的和整段收尾写的进同一张清单,只是标了是「第 n 句」还是「整段」。

## 快速开始

需要 **Python 3.10 或以上**。**没有别的依赖**——不用 `pip install`,不用 node,不联网就能跑起来。

```bash
git clone https://github.com/luluxiuc/Franklin-Writing.git
cd Franklin-Writing
python app/fk_server.py
```

浏览器会自动打开 `http://127.0.0.1:8137`。

**Windows** 也可以双击 `启动.cmd`;**macOS / Linux** 用 `./启动.sh`。

常用参数:

```bash
python app/fk_server.py --port 9000          # 换端口(默认 8137,被占会自动往后找)
python app/fk_server.py --data D:\我的书库    # 换数据目录
```

服务只监听 `127.0.0.1`,同一个局域网里的其他机器也连不上。

### 可选:填一个 API Key

点右上角「设置」,选一家服务商,粘上 API Key,点「测试连接」。

- 支持 DeepSeek、OpenAI、通义千问、Kimi、智谱、OpenRouter、本地 Ollama,以及任何 OpenAI 兼容接口。
- Key 只存在你这台机器的 `app/data/index.json` 里,不会上传。
- **不填也能用**:只是没有提示卡,你会直接凭记忆写。**这其实更接近富兰克林原本的做法。**
- Key 里混进中文或空格(从网页复制时很常见)会被当场拦住并说明原因,不会等到发请求时报一个看不懂的编码错误。

## 怎么用

### ① 导入一篇文章

点书架上的「＋ 导入一本书」。可以填一个本地 `txt` / `md` 文件的路径,或者直接把文章粘进去。

工具会自动切成**节**(阅读单位)和**段**(练习单位),默认每段约 300 字,可以调。导入时只对空白做一次规整(行内多余空白压成一个、连续空行最多留一个),**一个实字都不动**——"按段拼回去等于原文"这条断言在测试里是硬性的。

### ② 读原文

在书内目录点任意一段。这时候原文完整地在你眼前。

### ③ 搁几分钟

读完点「读完了,去写这一段」。原文合上,进入倒计时。

> 这几分钟是这个方法的关键。等的时候可以去练别的段——书内目录里每段的状态都在,几段轮着练,等的时间就浪费不了。

### ④ 逐句提示在左边,稿纸在右边,原文不在

倒计时结束,进入写作台。**原文的任何一个字都不在这里。**

左边是逐句提示:原文有几句话,就有几条提示,一条对一句。

```
1  讲家乡端午的几种风俗
2  列举系百索子、做香角子这类做法
3  说符的来历,以及那位道士和作者的关系
```

写不下去就空着,别编。写完按 `Ctrl+Enter` 或者点「写完了,看对照」。

**想一句一句练,点提示栏最上面那个「一句一句单独练」。** 看一条提示,只写这一句,写完立刻和原文那一句并排——你写出来的词会被底色标出来。

### ⑤ 对照:一句一句对着看

交稿的瞬间,页面变成逐句配对:**每一句原文**下面就是**你写的那一句**,两句头上还挂着当时那条提示。多写的、漏写的会被单独标出来。

再往下是:

- 你写出来的词会被底色标出(原文里也有、你也写到的那些)。
- **原文里有、你没写到的片段**,原样摆出来,不评价。
- 想逐词看,展开「按词看」。

最后写一句「我看到的差别」。一句就够,比如"第二句我把因果省了"、"我把三个短句连成了一个长句"。**这条会收进这本书的笔记。**

## 提示是怎么做到又省 token 又不泄露措辞的

「调用大模型」最容易变成一个悄悄烧钱的黑洞。这一段的每一条都是为了堵它。

| 机制 | 做法 |
| --- | --- |
| **同一段文字只生成一次** | 缓存键是**原文内容的哈希 + 模型名 + 提示词版本**,跟这段文字在哪本书、第几节第几段**无关**。所以同一段文字第二次要用直接读本地;一本书里重复的段落只做一次;换模型或改提示词会让旧缓存自动失效,不需要手工清理。 |
| **能提前做就不用等** | 「提前备好」在后台把整本书的提示做完(默认并发 2,`FK_LLM_CONCURRENCY` 可调,免费额度小建议设 1)。练到那一段时提示已经在本地——**练的时候不用等模型**。 |
| **条数由句子数决定,单条字数封顶** | 一条提示对应一句原文,所以**条数不是模型说了算的**。单条上限:≤4 句时 22 字,≤8 句时 18 字,更多时 15 字。输出 token 直接由「句数 × 单条上限」封顶。 |
| **先算账再花钱** | 批量生成前会显示"还要做几段、大约多少 token",量大的时候再确认一次。估算明确标注是**估算**。 |
| **账目只记真实数字** | 设置页显示的是服务商**回传的** `usage`。拿不到就记 0 并单独说明,**不估算、不假装知道**。可以直接拿去对账单。 |
| **照抄原文的提示会被摘掉** | 逐条做机械检查:任何一条里出现连续 8 个字以上与原文逐字相同就摘掉那一条。两次都在抄就一条都不给。**这条不只是省钱——提示一旦给了原文的句子,你就不是在凭记忆写,练习直接失效。** |
| **短段不做** | 少于 40 字的段落跳过批量生成:那点内容做提示不划算,而且你本来也记得住。 |

## 它不做什么

- **不评分。** 没有分数、没有相似度、没有"像不像作者"、没有排名、没有等级。
- **不评价你的稿子。** 不说哪里该改,不给建议。
- **不替你写。** 除了给每句话配一条提示,不生成任何一句话。
- **不给你看"你进步了多少"。** 只摆原始记录,规律你自己看。
- **不联网**(除非你用了提示功能)。语料和稿子都不出这台机器。

对照页只做一件事:把两份文本和一份机械比对的结果摆在你面前。**判断是你的。**

## 测试

```bash
python tests/run_all.py
```

| 套件 | 检查什么 |
| --- | --- |
| 数据层 | 切分是可逆的(原文一个字不丢)、分段有兜底、存档读写、状态机 |
| 提示卡 | 逐句条数对不对得上、缓存命中、账目真实性、批量生成、错 Key 怎么收场、照抄检查 |
| 服务层 | 端到端 HTTP;**写稿阶段任何接口都不返回原文**、笔记挂在书上 |
| 前端契约 | JS 引用的元素和接口是否都存在(防"点了没反应") |
| 按钮点得动 | 把模板真渲染出来,找出每个按钮,点了看状态有没有跟着变 |
| 输入动效 | 只对落定的字做动画、三档画法确实不同、动画量不随文章长度增长、能挂能拆 |
| 前端渲染 | 在 Node 里真跑一遍每个页面的渲染,用真实接口数据 |

一共 **378 项**检查(`runner` 自己报的数)。它自己起一个带假模型的服务来跑渲染检查,跑完关掉——不依赖你手动开服务,也不会真的调模型花钱。

有几条自检值得单独说,它们都是**开发过程中真的抓到过问题**才加上的:

- **写稿接口在返回之前会拿原文反查一遍自己要发出去的数据**,发现疑似泄露就直接拒绝服务。它抓到过:某一节的标题是从原文首句截出来的,而它被挂在了练习页的标题栏上,等于把这一段的开头送给了你。
- **同一类自检抓到模型把原文一整句搬进了提示。** 现在这种情况在生成那一步就会被摘掉。
- **分段兜底**:粘 2000 字没有句读的内容进去,原来会被当成"一段",练一次要背 2000 字。现在句内还会按标点切、再不行按字数硬切。
- **按钮真的点得动**:前两次修动效按钮都没修对,原因是只验了"数据不同",没验"点击通不通到代码里"。现在这条是硬断言。

## 这个研究本身的局限

**我们把自己研究里的问题写在这里,因为一个声称自己诚实的项目不能只报有利的数据。**

| 局限 | 说明 | 状态 |
| --- | --- | --- |
| **人类一致率从未测过** | 裁判全部是 LLM,构成循环——测的是自一致性,不是与人类专家的一致性。工具已备好(`_capability/human_kit.py`),**需要 3 位以上合格读者各标一次**。 | 待做 |
| **检索通道没被剥离** | 5 位裁判中有 3 位违规检索并核实了出处,协议明确要求不得推测作者身份。**所以「真实文本 0% 误判」不能完全归功于风格辨识能力**,部分来自记忆检索。而用户的真实需求恰恰是非名篇语料。 | 待做 |
| **补充的同长度配对检验失效** | 严格配平到同字数后,裁判的理由是"乙的两句与原文逐字一致,属原文截取"并附了检索链接——它绕过了风格比较,直接查到了出处。 | 已记录 |
| **实验二(单句判别)已设计未执行** | 把作者原句与"同内容、同字数、同名物、只换写法"的改写配对做二选一,这样才能把"风格判断"与"篇幅判断"彻底分离。 | 待做 |
| **执行者既造材料又设计实验** | 模仿稿必然带执行者自己的风格指纹。若裁判能挑出它,无法区分"认出了作者的笔法"与"认出了执行者的笔法"。彻底的解法是换一位写作者来造材料。 | 结构性限制 |
| **样本量小** | 18 块、5 位裁判,只能给出方向性结论,不足以给出精确的能力上界。 | 已记录 |
| **预注册规则漏掉了真正的失效模式** | 预注册的触发条件是"A 类误判率 ≥ 37.5%",实测 0%,未触发。真正的失效是"把称职的判成真的"(漏检),当时没预见到。修正判定的推理过程已一并写明,以免变成事后挑选标准。 | 已记录 |

**但这些局限只能加强结论,不能推翻它**:因为该判断在人类之间本身就不稳定,而分歧恰好集中在用户会遇到的那类文本上。详见[决策报告第 4.3 节](docs/研究/为什么不做LLM判断评分.md)。
