# fk — 富兰克林写作法工具（无判断版）· 命令行原型

> **这个原型已经被网页版取代。** 现在请用根目录的 `启动.cmd`（或 `启动.sh`），
> 说明见 [`docs/设计/工具使用说明.md`](../docs/设计/工具使用说明.md)。本目录保留下来只作记录：
> 网页版的引擎 `app/fk_core.py` 就是从 `fk.py` 长出来的，约束自检的雏形也在这里。

把富兰克林写作法做顺手。**系统负责切分、提示、隐藏、记录；理解与评判完全由你自己完成。**

本工具**不做任何关于"写得好不好""像不像作者"的判断**，**不调用任何模型**，可完全离线运行。

---

## 为什么是无判断版

这个决定不是设计偏好，是实测结论。我们用 8 段真实原文 + 10 段 AI 模仿（5 段无缺陷、5 段各植入一个具名缺陷）做了 18 个匿名文本块的归属测试，5 个独立 LLM 裁判：

| 指标 | 结果 |
| --- | --- |
| 真实文本被误判为模仿 | 0%（5 位裁判全部判对 8/8） |
| 植入明显缺陷的模仿被识破 | 100%（5 位裁判全部识破 5/5） |
| **无缺陷的模仿被识破** | **0%**（5 位裁判中 3 位的成绩是 0/5） |

更严重的是误判的方向：裁判给出的理由是**拒绝作者本人的特征**——把"留白收束""自我不确定的元陈述"当作破绽，而这些正是该作者的标志性手法。有裁判甚至**编造语言证据**（声称"一个线轴只缠一色线"）来支撑一个风格判断。

**结论：** LLM 能做的是"缺陷检测"（靠一份黑名单），不是"风格辨识"。用缺陷检测冒充风格判断去做训练反馈，会稳定地把用户推离目标作者。

于是这个工具只保留不依赖判断的部分。完整研究记录见 `_capability/实验一最终结果.md`。

## 安装与运行

只依赖 Python 3.8+ 标准库。

```bash
python fk.py import 范文.txt --title "汪曾祺《端午的鸭蛋》" --size 150
python fk.py status
python fk.py write   <作品id> 1
python fk.py compare <作品id> 1
python fk.py list    <作品id>
```

`--size` 是每个训练单元的目标字数（默认 150）。切分**只按规模**，不判断"表达动作"——那是一种解读。

## 一次训练长什么样

**1. `write` — 临摹**

原文隐藏。系统只给一份**机械抽取的内容片段清单**：

```
家乡　端午　多风俗　外地　索子　丝线拧成　小绳　手腕　丝线　掉色　洗脸　印得红
```

这些片段全部是原文里真实存在的连续子串，用横跨扫描 + 已覆盖标记抽出，**不含任何写法说明、不含修辞名称**。提示可以不用。

在提示下方凭记忆重写这一段，粘贴后以 `END` 结束。记不清就空着——**系统不会给你更多提示，也不会递梯子。**

**2. 延迟**

提交后默认**强制等待 10 分钟**才能看原文。这是富兰克林方法里最关键的一步（让记忆脱离短时缓冲）。`--skip-delay` 可以跳过，但你要知道自己跳过了什么。

**3. `compare` — 并置对照**

```
原　文                          │你的稿子
==============================================================================
家乡的端午，很多风俗和外地一样。      │家乡的端午，很多风俗和外地一样。
系百索子。                       │因为要系百索子，所以人们把五色的丝线拧成小绳，
五色的丝线拧成小绳，系在手腕上。      │系在手腕上，让我感到非常温暖。
丝线是掉色的，洗脸时沾了水……        │
==============================================================================

【具体名物】以下是机械比对结果，只列事实，不评价。
  出现（9）：家乡、端午、多风俗、外地、索子、丝线拧成、小绳、手腕、丝线
  未出现（5）：掉色、洗脸、印得红、道绿、做香角子

  未出现不等于写得不好——可能是有意省略。判断在你自己。
```

覆盖率是**纯子串比对**，不换算成分数，不说"你记住了多少"。

**4. 我的观察（硬性）**

```
【我的观察】请写下你自己看到的差异。系统不会替你判断。
看不出差别也可以，但必须写出来。
```

不写下观察，本单元不算完成。**去掉 AI 判断之后，观察就是唯一的学习动作。**

## 设计约束（硬性，写在代码里）

| 约束 | 落实方式 |
| --- | --- |
| 不做判断 | 全部代码不含评分、接近度、优劣结论 |
| 不调用模型 | 无任何网络依赖，可离线 |
| 提示只给片段 | 抽取结果必为原文连续子串，无写法说明 |
| 覆盖率只列事实 | 只报命中/未命中，不换算分数 |
| 强制脱离原文 | 提交后默认不可覆盖（`--force` 才可重来） |
| 强制延迟 | `compare` 校验提交时间戳 |
| 强制观察 | 无观察则不落库完成时间 |
| 档案不归纳 | 只展示原始记录，不下"你总是…"这类结论 |

约束自检：`python selftest.py`　端到端测试：`python e2e_test.py`

## 状态存储

全部在 `state/library.json`，纯本地、无服务端。每个单元记录：原文、机械提示、你的稿子、提交时间、覆盖率清单、你的观察、对照时间。

## 路线图（未做）

- **迁移训练**：换题材重写，由你自己对照两次作品，不由系统判断。
- **流程完成度**：记录"是否脱离原文、是否等待、是否写下观察"，只记动作，不记好坏。
- **导出**：把对照记录导成可打印的并排文档。

**不会做：** 账号、云同步、范文社区、范文推荐、任何形式的评分或排名。
