# 富兰克林写作

一个本地的写作练习工具。**导入一本书或一段文章，读原文，过几分钟，凭记忆把它重写出来，然后跟原文对照。**

网页版，跑在你自己电脑上。数据全部留在本地。只有「把原文概括成提示」这一步会用到一次大模型，而且填不填 Key 都能用。

---

## 怎么用

### 1. 打开

**Windows（最省事）：在任何地方敲 `fk` 回车。**

打开终端（开始菜单搜「终端」或 Win+R 输 `cmd`），敲：

```
fk
```

在哪都行，不用先 cd 到项目目录，也不用记路径。服务没开就启动它，已经开着就直接把页面打开——**不会起第二个实例**。

> 这个命令是怎么来的：是一个放在 PATH 目录里的 `fk.cmd`，里面写死了项目位置。
> 它不随仓库分发（每个人的项目位置不一样），**换电脑需要重新生成一次**。

**Windows（不碰命令行）：双击 `启动.cmd`。** 浏览器会自动打开。

> 这个文件**必须保持纯 ASCII**。cmd.exe 按系统 OEM 代码页（中文 Windows 上是 GBK）
> 逐行解析批处理，正文里只要有一个中文，多字节字符就会被截断，剩下的字节被当成
> 命令执行——表现是**双击后窗口闪一下、服务根本没起**。这个 bug 真发生过，
> 所以现在提示语是英文，并且测试里有一条专门盯着它（`tests/docs_check.py` 第四节）。

**macOS / Linux：**

```bash
./启动.sh
```

**手动：**

```bash
python app/fk_server.py              # 默认 127.0.0.1:8137，端口被占会自动往后找
python app/fk_server.py --port 9000
python app/fk_server.py --data D:\我的书库
```

需要 Python 3.10 或以上。**没有别的依赖** —— 不用 pip install，不用 node，不用联网就能跑起来。

服务只监听 `127.0.0.1`，同一个局域网里的其他机器也连不上。

### 2. 第一次：填个 Key（可选）

点右上角「设置」，选一家服务商，粘上 API Key。

- 支持的：DeepSeek、OpenAI、通义千问、Kimi、智谱、OpenRouter、本地 Ollama，以及任何 OpenAI 兼容接口。
- Key 存在 `app/data/index.json` 里，只在这台机器上，不会上传。
- **不填也能用**：只是没有提示卡，你会直接凭记忆写。这其实更接近富兰克林原本的做法。
- Key 里混进中文或空格（从网页复制时很常见）会被当场拦住并说明原因，
  不会等到发请求时报一个看不懂的编码错误。

点「测试连接」确认通了。**整个工具只在这一个地方花钱**，而且很省，见文末。

### 3. 导入一本书

点书架上的「＋ 导入一本书」。可以：

- 填一个本地 txt / md 文件的路径；
- 或者直接把文章粘进去（网页上看到的好文章，选中、复制、粘贴）。

工具会自动切成**节**（阅读单位）和**段**（练习单位）。默认每段约 300 字，可以调。

**导入时可以顺手把提示提前备好。** 书内目录顶部有一行「逐句提示 0 / 37 段已备好」和一个
「提前备好」按钮。点它会在后台把整本书的提示都做好，你可以同时去读书——
练到那一段的时候，提示已经躺在本地了，不用等模型。

按之前会先告诉你大概要花多少 token，超过一定量还会再确认一次。不点也完全没关系，
练到哪一段就现场做那一段的，一样用。

### 4. 练一段：四步

**① 读原文**
在书内目录点任意一段，或者从第一节开始读。这时候原文完整地在你眼前。

**② 搁几分钟**
读完点「读完了，去写这一段」。原文合上，进入倒计时（默认 3 分钟，可以在设置里改成 0～240 分钟）。

> 这几分钟是这个方法的关键。刚读完就写，写出来的是眼睛里残留的字；等几分钟再写，写出来的才是记住的东西。
>
> 等的时候可以去练别的段——书内目录里每段的状态都在，几段轮着练，等的时间就浪费不了。

**③ 逐句提示在左边，稿纸在右边，原文不在**

倒计时结束，进入写作台。**原文的任何一个字都不在这里。**

左边是**逐句提示**：原文有几句话，就有几条提示，一条对一句。比如

```
1  讲家乡端午的几种风俗
2  列举系百索子、做香角子这类做法
3  说符的来历，以及那位道士和作者的关系
```

为什么是一句一条，而不是把整段概括成几条——因为富兰克林原本就是这么做的：
他读一篇文章，**给每一句话记一条短提示**，搁几天，再看着这些提示把整篇写回来。
而且这个练习要练的本来就是"写好每一句话"，所以提示的单位就该是句子。
段落概括会把原文重新组织一遍，那个结构是模型的，不是你的。

提示只给"这句讲了什么"，**不给措辞、不给写法、不评价**，而且工具会机械检查：
**任何一条里只要出现连续 8 个字以上与原文逐字相同，这条就丢掉**——给原文的句子
等于让你抄，那样练了也没用。

你可以：用它当抓手；或者点「不用提示，凭记忆写」把它关掉；或者点「重新生成」换一版。
写不下去就空着，别编。写完按 `Ctrl+Enter` 或者点「写完了，看对照」。

**想一句一句练，点提示栏最上面那个「一句一句单独练」。**
看一条提示，只写这一句，写完立刻和原文那一句并排——你写出来的词会被底色标出来，
下面还列出"这一句里有哪些词你也写到了"。

**④ 对照：一句一句对着看**

交稿的瞬间，页面变成逐句配对：**每一句原文**下面就是**你写的那一句**，
两句头上还挂着当时那条提示。

配对不是简单地"第 n 句对第 n 句"——你漏写一句，后面就全错位了，那显示的是假信息。
所以工具用最长公共子序列来对齐：多写的、漏写的单独标出来，其余各就各位。

再往下是：

- 你写出来的词会被底色标出来（原文里也有、你也写到的那些）。
- **原文里有、你没写到的片段**，原样摆出来，不评价。
- 想逐词看，展开「按词看」。

最后写一句「我看到的差别」。一句就够，比如"第二句我把因果省了"、"我把三个短句连成了一个长句"。
**这条会收进这本书的笔记**——和单句练习里记的笔记放在同一个地方。

## 笔记：一个入口，跟着书走

不管在哪一步写的，都进同一张清单：

- **单句练习**里，写完对照可以在下面记一条——它自动带上**那一句的原文、你写的、以及那条提示**。
- **整段练习**收尾时写的那一句（以前叫「我的观察」），也是一条笔记，只是范围标成「整段」。

回到书内目录，下面就列着**这本书的全部笔记**，按时间倒序。每条都标着是「第 n 句」还是「整段」，
以及在第几节第几段。可以单条删，也可以一键导出成 markdown。

> **为什么合并入口**：以前「我的观察」和「逐句笔记」是两个入口、两份数据，
> 你得记住"我这句感想该写在哪"。现在只有一个地方可写、一个地方可看。
>
> **为什么还分逐句和整段**：因为它们是两种东西——"这一句我把因果省了"是能改的，
> "这一段的节奏我整体写散了"是另一种观察。合并的是入口，不是内容。

## 输入时的字效

写作台和单句练习的输入框里，**你打上去的字**会有一次入场动画。
四个档在输入框旁边的「动效」那一组小按钮里选：**淡入 / 升起 / 书写 / 关**，选了会记住。

三档是真的三种画法，不是同一个动画改个名字：

| 档位 | 时长 | 画法 |
| --- | --- | --- |
| 淡入 | 280ms | 在原地很轻地放大一点、淡进来 |
| 升起 | 300ms | 从下方浮上来落定 |
| 书写 | 340ms | 从下往上擦出来，带一道跟着走的笔尖 |

**三个关键决定，都是踩过坑才定下来的：**

**一、只对"落定的字"做动画，不管用什么输入法。**
中文打字时，输入框里会先出现拼音字母或候选词，然后才定成一个汉字。
如果跟着每一次输入事件做动画，动效就散在一堆中间状态上——这正是第一版"效果不明显"的原因，
方向做反了。现在等输入法定字那一刻，或者字直接上屏之后才动。

**二、动画的就是输入框里那个字本身。**
它就在原位放大着落定，你看到的是"这个字刚刚被写上去"，而不是旁边多冒出一个字。

**三、不碰输入框里的文字。** canvas 盖在上面，字体字号从输入框上量。
给每个字包一个元素会毁掉中文输入法、选区和撤销，而且写到一千字就卡。

**性能上有几道硬闸**（都有测试盯着）：一次最多让 **40 个字**动起来——贴 6000 字和贴 180 字
安排的字数一样，**动画量不随文章长度增长**；同屏字符有上限；删除和移动光标不触发；
选「关」之后一行动画代码都不跑。

## 逐句提示是怎么省钱的

这一段值得单独说，因为"调用大模型"最容易变成一个悄悄烧钱的黑洞。

**一、同一段文字只生成一次。**
缓存的键是**原文内容的哈希 + 模型名 + 提示词版本**——跟这段文字在哪本书里、第几节第几段**无关**。
所以：

- 同一段文字第二次要用，直接读本地，一次调用都不发生；
- 一本书里如果有一段和另一段重复（诗歌、反复出现的句式），只做一次；
- 换模型会让旧缓存失效（不同模型的说法本来就不一样，这是有意的）；
- 改提示词也会让它失效（版本号写进了缓存键里），不需要你手工清理。

缓存存在 `app/data/summaries.json`，纯文本。删掉它不影响原文和你的稿子。

**二、能提前做，就不用等。**
「提前备好」在后台把整本书的提示做完（默认并发 2，可用环境变量
`FK_LLM_CONCURRENCY` 调；免费额度小的接口建议设成 1）。等你练到那一段，
提示已经在本地了——**练的时候不用等模型**，这是最主要的体验差别。

**三、条数由句子数决定，单条字数封顶。**

一条提示对应一句原文，所以**条数不是模型说了算的**，是原文有多少句就有多少条
（模型少给了会如实报不对齐，多给了会截断）。单条的字数上限：

| 这一段有几句 | 每条最多多少字 |
| --- | --- |
| ≤ 4 句 | 22 |
| ≤ 8 句 | 18 |
| 更多 | 15 |

输出 token 直接由「句数 × 单条上限」封顶。原文超过 2200 字会先截断——
再长下去，多出来的字基本只增加成本，对你"想起这一段讲了什么"没有帮助。

**四、先算账，再花钱。**
「提前备好」之前会显示"还要做几段、大约多少 token"，量大的时候再确认一次。
估算按汉字折算，明确标注是**估算**——它只用来让你心里有数。

**五、账目只记真实数字。**
设置页显示的是服务商**回传的** `usage`（输入/输出 token、调用次数、命中次数）。
拿不到就记 0 并单独说明，**不估算、不假装知道**。你可以拿它直接对账单。

**六、模型照抄原文的提示会被摘掉。**
提示词里明确要求"绝不能复用原文的词句"，但模型偶尔还是会偷懒，把原文一小句搬进来。
工具在存缓存之前会**逐条**做机械检查：**任何一条里出现连续 8 个字以上与原文逐字相同，
就摘掉那一条**（只摘那一条，不牵连别的）。如果一条不剩，就重新生成一次
（最多一次，不和模型的犟劲耗钱）；两次都在抄，就一条都不给——
与其把原文的句子塞回给你，不如让你纯粹凭记忆写。

这条不只是省钱：提示一旦给了原文的句子，你就不是在凭记忆写，练习直接失效。

**七、短段不做。**
少于 40 字的段落跳过批量生成：那点内容做提示不划算，而且你本来也记得住。

## 它不做什么

- **不评分。** 没有分数、没有相似度、没有"像不像作者"、没有排名、没有等级。
- **不评价你的稿子。** 不说哪里该改，不给建议。
- **不替你写。** 除了给每句话配一条提示，不生成任何一句话。
- **不给你看"你进步了多少"。** 只摆原始记录，规律你自己看。

对照页只做一件事：把两份文本和一份机械比对的结果摆在你面前。判断是你的。

## 数据在哪

全在 `app/data/`：

```
app/data/
  index.json        书目、每一轮的稿子、观察、笔记、设置（含 API Key）
  index.json.bak    上一版，改坏了可以退回来
  texts/<书id>.txt  每本书的原文，一篇一个文件
```

都是纯文本。你可以直接打开看、复制、备份，换台电脑把整个 `app/data` 拷过去就能接着用。

**删掉这个目录 = 完全没在这个工具上留下任何东西。**

每一轮练习还可以单独导出成 markdown（对照页上的「导出这一轮」），里面是逐句提示、原文、你的稿子、你的观察。

## 测试

```bash
python tests/run_all.py
```

| 套件 | 检查什么 |
| --- | --- |
| 数据层 | 切分是可逆的（原文一个字不丢）、分段有兜底、存档读写、状态机 |
| 提示卡 | 逐句条数对不对得上、缓存命中、账目真实性、批量生成、错 Key 怎么收场、照抄检查 |
| 服务层 | 端到端 HTTP；**写稿阶段任何接口都不返回原文**、笔记挂在书上 |
| 前端契约 | JS 引用的元素和接口是否都存在（防"点了没反应"） |
| 输入动效 | 只对落定的字做动画、三档画法确实不同、动画量不随文章长度增长、能挂能拆 |
| 前端渲染 | 在 Node 里真跑一遍每个页面的渲染，用真实接口数据 |

一共 360 多项检查。runner 会自己起一个带假模型的服务来跑渲染检查，跑完关掉——
所以不依赖你手动开服务，也不会真的调模型花钱。

有几条自检值得单独说，它们都是**开发过程中真的抓到过问题**才加上的：

- **写稿接口在返回之前会拿原文反查一遍自己要发出去的数据**，发现疑似泄露就直接拒绝服务。
  它抓到过：某一节的标题是从原文首句截出来的，而它被挂在了练习页的标题栏上，
  等于把这一段的开头送给了你。现在练习页不显示节标题。
- **同一类自检抓到模型把原文一整句搬进了提示**。现在这种情况在生成那一步就会被摘掉。
- **分段兜底**：粘 2000 字没有句读的内容进去，原来会被当成"一段"，练一次要背 2000 字。
  现在句内还会按标点切、再不行按字数硬切，任何形态的粘贴都不会出现超长段。

## 一些设计上的取舍

**为什么笔记要落在"某一句话"上，而不是给整段写一段总结？**
因为落在具体一句话上的笔记是能改的——"这一句我把因果省了"下次就知道注意什么；
而"我写得不够好"改不了。而且笔记跟着书走、能随时翻，比每轮写一段感想有用得多。

**为什么导入时要把空白理一遍？**
从网页复制来的文章常带行首行尾空格，还可能有整行只有空白的行。
它们不影响内容，但会让切分产生一堆没内容的碎片，句子的编号也会飘。
所以导入时只对空白做一次规整（行内多余空白压成一个、连续空行最多留一个），
**一个实字都不动**——"按段拼回去等于原文"这条断言仍然成立。

**为什么输入动效要用 canvas 叠加，而不是给每个字包一个元素？**
前者只画几十个正在飞的字符，开销和文章长度基本无关，而且完全不碰输入框里的文字——
中文输入法、选区、撤销都不受影响。后者要维护一个可编辑的富文本区，
每个字一个节点，写到一千字就开始卡，输入法还容易出问题。

**为什么动效要等"字落定"才做，而不是跟着每次输入做？**
因为中文打字时输入框里会先出现拼音和候选词。跟着输入事件做动画，
动效就散在一堆中间状态上，看着乱、也不明显——读者感知到的是"这个字刚被写上去"，
而不是"拼音字母一个个冒出来"。

**为什么提示是"一句一条"，而不是把整段概括成几条？**
富兰克林自己的做法就是给每句话记一条短提示（"short hints of the sentiment of each
sentence"），搁几天，再看着提示把整篇写回来。而且这个练习要练的正是"写好每一句话"，
所以提示的单位就该是句子。段落概括还有两个问题：它会把原文重新组织一遍，那个结构是
模型的而不是你的；它也很容易把原文的措辞带进来，你照着写就成了抄写。

**为什么延迟放在"读完"和"开始写"之间，而不是交稿之后？**
延迟的目的是让读过的东西从眼前落进记忆，这样你写出来的才是"记住的"。放在交稿之后只是防止你偷看，防的是作弊，不是帮助记忆。

**为什么是"节 + 段"两层？**
读书要连贯，所以按节读；练记忆不能太长，所以按段练。一节的正文读完之后，可以逐段练。

**为什么切分要保证"一个字不丢"？**
原文只存一份，段的位置是原文里的坐标。所以"把每一段拼回去"必须精确等于原文。测试里把这条当成硬性断言——它是所有对照功能可信的前提。

**为什么对照页要按 LCS 对齐，而不是第 n 句对第 n 句？**
因为你一漏写，后面全错位，页面显示的就是假信息——比不显示更糟。现在多写的、漏写的
单独标出来，其余各就各位。

**为什么提示的缓存键里要带模型名和提示词版本？**
因为提示的内容取决于这两样东西。带着它们，换模型、改提示词时旧缓存自动失效，
你不用记得去清；同一段文字不管出现在哪本书里都只做一次，你也不用担心重复花钱。

**为什么照抄原文的那一条提示要摘掉，而不是留着让你参考？**
因为那一句你自己也能想起来了，留着只会让你照着它写。提示的价值在"帮你想起来讲了什么"，
一旦它开始给原文的句子，这个练习就变成了抄写。

**为什么账目只记服务商回传的数字？**
因为只有那才是真的。估算可以用来说"大概要花多少"，但不能写进账本——那会让你以为知道自己花了多少，其实不知道。
